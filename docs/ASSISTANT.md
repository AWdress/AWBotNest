# 系统助手

系统助手用于查询系统状态、检查插件任务和日志，也能调用插件明确开放的动作。它和插件里的聊天功能独立，使用系统已经配置的文字模型。

## 开始使用

1. 在「系统设置 → AI 服务」配置服务和文字模型，选择默认文字模型。
2. 点击顶部的「系统助手」，或 AI 服务页的「打开助手」。
3. 新建会话，例如输入「查看系统运行情况」「检查某个插件最近有没有报错」。
4. 可直接查询全部已安装插件的任务、日志和公开配置，无需再逐个勾选。

文字模型必须支持工具调用。系统支持 OpenAI Chat Completions、Responses 和 Anthropic Messages，不会把模型输出的普通文字当成命令执行。模型名相同不代表服务商一定支持同一协议，失败时可在 AI 服务页检查具体调用记录。

## 对话与执行

- 会话保存在 `data/assistant.db`，刷新或关闭网页不会丢失。新建会话可以切换话题。
- 执行步骤会显示正在分析、读取或执行的内容；用量显示本次各轮累计 Token。服务商不提供用量时显示估算值。
- 执行中可以补充要求，也可以停止任务。停止只影响尚未完成的部分，不会撤销已经完成的操作。
- 补充要求会立即保存。轮数或用量已用完、任务被停止时，未处理的补充会明确标出，可发送新消息继续。
- 桌面端可以扩大窗口；手机端使用全屏面板。关闭面板不会停止后台任务，重新打开可继续查看。
- 单个会话只能运行一个任务，系统最多接收 8 个活动任务，同一时间最多执行 2 个助手步骤；等待确认不会占用这两个执行名额。
- 回复逐步显示；接口不返回流时会等待完整结果。断流后会停止，不会拿未完成的工具参数继续操作。
- 缺少信息时，助手可以暂停追问。选择或回答只补充任务信息，不代表批准修改。多步骤任务可以显示计划和当前进度。
- 较早的对话会整理为摘要，再保留最近消息继续处理；摘要不继承以前的操作批准。完整记录仍受会话保留上限约束。

## 权限与确认

默认只允许查询。要执行插件动作，需要同时满足：

1. 插件通过 `ctx.action(..., agent_exposed=True)` 显式开放该动作。
2. 插件已安装，且动作当前可用。
3. 写入类动作还需要打开「允许执行修改操作」，并在本次操作的确认卡上批准。

确认绑定这次的具体参数、插件注册代次和配置状态，15 分钟内有效且只能使用一次。插件重载、配置变化或撤回授权后，旧确认不能继续执行。拒绝操作后，模型不能换一组参数再次申请同一个动作。

也可要求助手启用、停用或重新加载已安装插件。这类管理操作不需要插件额外提供动作，但必须确认；停用、重载可能中断正在运行的任务。确认后如果插件源码、配置、账号分配或运行代次发生变化，会停止执行并要求重新确认。

主系统不提供 Shell、任意文件读取或 Python 执行，不能读取密钥原值。可选的独立沙箱可运行代码、读写临时文件和操作浏览器，每次仍需确认，且没有系统配置、插件或账号目录。它不能直接安装、卸载插件、重启系统或改写插件配置。技能和记忆不会扩大权限。独立执行端的部署与限制见 [沙箱说明](ASSISTANT_SANDBOX.md)。

助手管理接口仅接受管理员登录令牌，不接受开放 API Key。Telegram 或企业微信普通成员不会因拥有消息白名单权限而获得助手管理员权限；需要在网页生成配对码，再到对应渠道完成配对。

## 图片、文件与语音

可以选择或粘贴图片。一次最多 3 张，单张不超过 5 MiB、合计不超过 8 MiB。需要在 AI 服务中配置默认视觉模型；系统先识别图片，再结合问题调用工具。图片中的文字、链接或“已批准”不能代替管理员确认。

支持 UTF-8 编码的 TXT、Markdown、JSON、CSV、TSV、YAML、TOML、INI 和日志文件，一次最多 3 个，文本合计不超过 10000 字节。附件只作为资料，不执行其中的代码或命令；不要上传密码、Cookie、密钥或会话文件。

语音须在「AI 服务」配置支持 OpenAI 音频转写接口的模型，勾选「语音转写」并设为默认。每条最多 8 MiB，不会使用文字模型猜测转写。Telegram 常见的 Ogg 和企微 AMR 是否可用取决于服务商；服务不接受时请改发文字或 WAV、MP3、M4A。系统不会自行转码或安装解码器。

原始图片和语音不写入会话数据库，只保存脱敏后的识别内容；文本附件保存脱敏文本。附件会发送给所配置的 AI 服务，请注意隐私。网页单次请求总上限为 12 MiB，图片和语音同时发送时还须满足总上限；超出后可移除部分附件重新发送。任务执行中可以补文字；附图、文件或语音请等当前任务结束后再发送。

## Telegram 与企业微信

在助手「设置 → 消息渠道」选择已配置的 Bot 或企微应用，生成一次性配对码。10 分钟内由本人私聊该 Bot，或向对应企微应用发送页面给出的 `/配对 代码`。企微仍须满足原有成员白名单和加密回调配置。

配对后发送 `/助手 你的要求` 进入助手模式，再发文字、图片、文本文件或语音即可继续对话。发送 `/退出助手` 后，普通消息恢复原来的插件处理；未配对成员和 Telegram 群消息不会获得助手权限。

- `/新会话`：开始新的对话。
- `/停止`：停止当前任务。
- `/确认 短码` 或 `/拒绝 短码`：处理对应的操作预览。完整预览发送成功后才可确认，短码不能跨成员或渠道使用。
- `/选择 短码 选项编号` 或 `/回答 短码 文字`：回答助手追问，不批准修改。

网页中可以刷新渠道状态和撤销配对。撤销后，旧消息、确认码和排队任务不能继续使用该授权。Bot 自动重连后会恢复入口，不需要重新配对。已接收但尚未交给助手的消息，以及尚未发送的结果，遇到短暂断线会等待恢复，最多 60 秒；已经提交或发送结果不明时，不会自动重试。

## 记忆与技能

「记忆」保存偏好，例如「检查结果用中文，先说异常项」；「技能」保存办事方法，例如排查步骤。可以在相应页签添加、编辑或删除，也可以要求助手提出保存，批准后才会保存。

记忆按关键词查询，技能按需读取，不会在每次请求中加载全部资料。关闭记忆后，不会向模型提供已保存的偏好。历史检索只搜索本助手会话，不读取其他插件的聊天或存储数据。搜索先返回命中附近的内容，助手可按返回的消息标识和分页位置继续读取；已保存的附件文本、语音转写和图片识别也可查询，不含原始媒体。

系统内置以下 5 项技能，可在「技能」页查看步骤，不能修改或删除：

- `awbotnest-api`：查询系统、插件、任务、公开配置和近期日志，区分事实与推测。
- `command-dispatch`：查找插件明确开放的动作，核对参数，写操作单独确认。
- `feedback-issue`：整理问题或建议，生成脱敏报告，确认后提交 GitHub Issue。
- `create-awbotnest-skill`：将可复用流程整理为自定义技能，不保存凭据或长期授权。
- `awbotnest-update`：读取系统已有的更新检查缓存，不安装、下载或重启。

目录只包含名称和用途；正文按需读取，较长内容按分页续读，不会静默丢掉尾部步骤。内置技能还配有排查示例、动作约定和反馈模板，可用 `list_skill_resources`、`read_skill_resource` 按需读取。它们是随系统提供的纯文本，不是任意文件读取或脚本执行入口。内置技能不占自定义技能的 50 项配额。这些流程参考 MP V3 的内置 Skill 设计，已按系统工具独立改写；不会执行 MP 的脚本或直接接入其媒体业务工具。

不要把密码、Cookie、密钥、验证码或会话内容保存为记忆或技能。系统会检查已知凭据并进行脱敏，但无法识别世界上所有未知秘密。

## GitHub 问题反馈

管理员明确要求提交问题或建议后，助手可以整理报告，生成本地草稿。未配置 GitHub Token 或未允许提交时，只能生成报告，不会访问 GitHub 创建 Issue。

要允许提交：

1. 在系统设置填写有目标仓库 Issue 写入权限的 GitHub Token，建议仅授权必要仓库的细粒度 Token。Token 不会发送给模型。
2. 在助手设置打开「允许执行修改操作」和「允许提交 GitHub Issue」。
3. 无需填写仓库。系统问题指向 `AWdress/AWBotNest`；插件问题由系统按该插件的安装来源识别。手动上传、来源未知或记录不完整时只整理报告，不猜测作者仓库。
4. 在确认卡审阅目标仓库、标题和完整脱敏正文，再批准本次提交。草稿修改后必须重新确认，原确认不能继续使用。

确认有效期为 15 分钟。提交前还会核对授权、Token、代理设置及草稿内容，任何变化都会停止。提交超时、取消或重启后结果不确定时，不会自动重发；先到 GitHub 查看是否已经创建。GitHub 明确拒绝提交时，修好配置后可以重新生成草稿，仍需重新确认。

GitHub Issue 通常公开可见。系统会去掉已知凭据、图片和直接提及账号的通知，但未知秘密和个人信息仍需管理员自行核对；不会自动附带配置文件、截图或完整日志，也不会自行提交诊断结果。

## 预约任务

可指定未来时间，或填写五段 Cron，例如 `0 9 * * *` 表示每天上午 9 点。时区为 `Asia/Shanghai`，周期至少 5 分钟，最多保存 32 个预约。

也可以在对话中说「明早九点检查某插件的运行情况」，助手会提出预约并等待确认。时间由系统提供给模型，确认时仍应核对实际时间和要求。

到时会创建一个新会话执行要求。忙碌时等待名额，不会因为没有空闲名额就直接丢弃任务。同一个预约还没结束时，不会重叠启动；积压的 Cron 触发会合并补跑一次。

预约不等于长期批准写操作。需要写入时仍会停在确认步骤，管理员打开助手后批准；过期则不执行。暂停或删除预约不取消已经开始的任务，应到相应会话停止。

在助手设置中打开「预约通知」后，会通过默认 Bot 发送执行结果或待确认提醒。默认关闭，不会自行向消息渠道发送会话内容。

系统重启后，已经开始却没完成的任务标记为「已中断」，不会自动重放不确定的操作。尚未开始且已到时间的预约会补跑一次。

## 用量和数据

默认每次最多 8 轮、16 次工具调用、32000 Token 预算，单步超时 120 秒。预算包含重复发送的上下文和工具定义，并保守估算，不等同于服务商账单。服务商拒绝请求或超时也可能计费，请以其账单为准。

系统最多保留 100 个会话、每个会话 80 条消息、200 次执行记录、100 条记忆、50 项自定义技能和 20 份反馈草稿；活动中的任务会保留到结束，结果不确定的反馈草稿不自动淘汰。单个会话还有大小限制，过长时移除最早的消息。较长普通工具结果会标明截断；技能分页和待提交反馈保留完整内容，但仍受本次上下文预算限制。SQLite 操作在线程中完成，不需要 Redis、向量数据库或额外常驻模型。

## 外部工具与联网

「MCP 外部工具」默认关闭。管理员可以添加最多 4 个公网 HTTP(S) MCP 服务，再读取工具目录。需要 Token 的服务必须使用 HTTPS；Token 只保存在系统中，不交给模型。不能添加本机、内网、stdio 或可执行命令。

默认每次 MCP 调用都要确认。只有管理员在服务设置中明确标为只读的工具，才允许直接查询；不要仅凭服务端自己的只读标记放行。更换地址、凭据、权限或工具定义后，旧确认会失效。调用结果不确定时不自动重试。

「公网搜索与阅读」默认关闭。开启后可检索公开网页、分页阅读静态正文。搜索服务不可用时会直接说明；不登录网站、不执行 JavaScript、不读取浏览器 Cookie，也不访问内网或下载文件。

助手还可以将最多两个独立问题交给只读子助手分别查询。子助手与主任务共享预算和并发限制，不能修改、预约、提交 Issue 或继续派生助手；查询结果仍需主助手核实。

这些是通用助手能力。媒体搜索、订阅、下载和整理等业务需要对应插件提供动作，并非安装助手后就拥有 MoviePilot 的媒体业务。
