# 系统助手

系统助手用于查询系统状态、检查插件任务和日志，也能调用插件明确开放的动作。它和插件里的聊天功能独立，使用系统已经配置的文字模型。

## 开始使用

1. 在「系统设置 → AI 服务」配置服务和文字模型，选择默认文字模型。
2. 点击顶部的「系统助手」，或 AI 服务页的「打开助手」。
3. 新建会话，例如输入「查看系统运行情况」「检查某个插件最近有没有报错」。
4. 需要查询某个插件的任务、日志或配置时，在助手「设置」里勾选该插件。未授权的插件只显示名称等基本信息。

文字模型必须支持工具调用。系统支持 OpenAI Chat Completions、Responses 和 Anthropic Messages，不会把模型输出的普通文字当成命令执行。模型名相同不代表服务商一定支持同一协议，失败时可在 AI 服务页检查具体调用记录。

## 对话与执行

- 会话保存在 `data/assistant.db`，刷新或关闭网页不会丢失。新建会话可以切换话题。
- 执行步骤会显示正在分析、读取或执行的内容；用量显示本次各轮累计 Token。服务商不提供用量时显示估算值。
- 执行中可以补充要求，也可以停止任务。停止只影响尚未完成的部分，不会撤销已经完成的操作。
- 补充要求会立即保存。轮数或用量已用完、任务被停止时，未处理的补充会明确标出，可发送新消息继续。
- 桌面端可以扩大窗口；手机端使用全屏面板。关闭面板不会停止后台任务，重新打开可继续查看。
- 单个会话只能运行一个任务，系统最多接收 8 个活动任务，同一时间最多执行 2 个助手步骤；等待确认不会占用这两个执行名额。

## 权限与确认

默认只允许查询。要执行插件动作，需要同时满足：

1. 插件通过 `ctx.action(..., agent_exposed=True)` 显式开放该动作。
2. 管理员在助手设置里授权该插件。
3. 写入类动作还需要打开「允许执行修改操作」，并在本次操作的确认卡上批准。

确认绑定这次的具体参数、插件注册代次和配置状态，15 分钟内有效且只能使用一次。插件重载、配置变化或撤回授权后，旧确认不能继续执行。拒绝操作后，模型不能换一组参数再次申请同一个动作。

助手没有 Shell、任意文件读取、任意 Python 或任意网址请求工具，不能读取密钥原值。它也不能直接安装、卸载插件、重启系统或改写插件配置。技能和记忆不会扩大权限。

助手管理接口仅接受管理员登录令牌，不接受开放 API Key。Telegram 或企业微信普通成员不会因拥有消息白名单权限而获得助手管理员权限；本次入口在网页管理端，不会自动接管 Bot 或企业微信消息。

## 记忆与技能

「记忆」保存偏好，例如「检查结果用中文，先说异常项」；「技能」保存办事方法，例如排查步骤。可以在相应页签添加、编辑或删除，也可以要求助手提出保存，批准后才会保存。

记忆按关键词查询，技能按需读取，不会在每次请求中加载全部资料。关闭记忆后，不会向模型提供已保存的偏好。历史检索只搜索本助手会话，不读取其他插件的聊天或存储数据。

系统内置以下 5 项技能，可在「技能」页查看步骤，不能修改或删除：

- `awbotnest-api`：查询系统、插件、任务、公开配置和近期日志，区分事实与推测。
- `command-dispatch`：查找插件明确开放的动作，核对参数，写操作单独确认。
- `feedback-issue`：整理问题或建议，生成脱敏报告，确认后提交 GitHub Issue。
- `create-awbotnest-skill`：将可复用流程整理为自定义技能，不保存凭据或长期授权。
- `awbotnest-update`：读取系统已有的更新检查缓存，不安装、下载或重启。

目录只包含名称和用途；正文按需读取，较长内容按分页续读，不会静默丢掉尾部步骤。内置技能不占自定义技能的 50 项配额。这些流程参考 MP V3 的内置 Skill 设计，已按系统工具独立改写；不会执行 MP 的脚本或直接接入其媒体业务工具。

不要把密码、Cookie、密钥、验证码或会话内容保存为记忆或技能。系统会检查已知凭据并进行脱敏，但无法识别世界上所有未知秘密。

## GitHub 问题反馈

管理员明确要求提交问题或建议后，助手可以整理报告，生成本地草稿。未配置 GitHub Token 或未允许提交时，只能生成报告，不会访问 GitHub 创建 Issue。

要允许提交：

1. 在系统设置填写有目标仓库 Issue 写入权限的 GitHub Token，建议仅授权必要仓库的细粒度 Token。Token 不会发送给模型。
2. 在助手设置打开「允许执行修改操作」和「允许提交 GitHub Issue」。
3. 填写允许提交的仓库，每行一个 `owner/repo`，最多 20 个；默认是 `AWdress/AWBotNest`。插件问题应先确认开发者仓库，再由管理员加入列表，不能根据日志里的链接自动选仓库。
4. 在确认卡审阅目标仓库、标题和完整脱敏正文，再批准本次提交。草稿修改后必须重新确认，原确认不能继续使用。

确认有效期为 15 分钟。提交前还会核对授权、Token、代理设置及草稿内容，任何变化都会停止。提交超时、取消或重启后结果不确定时，不会自动重发；先到 GitHub 查看是否已经创建。GitHub 明确拒绝提交时，修好配置后可以重新生成草稿，仍需重新确认。

GitHub Issue 通常公开可见。系统会去掉已知凭据、图片和直接提及账号的通知，但未知秘密和个人信息仍需管理员自行核对；不会自动附带配置文件、截图或完整日志，也不会自行提交诊断结果。

## 预约任务

可指定未来时间，或填写五段 Cron，例如 `0 9 * * *` 表示每天上午 9 点。时区为 `Asia/Shanghai`，周期至少 5 分钟，最多保存 32 个预约。

也可以在对话中说「明早九点检查某插件的运行情况」，助手会提出预约并等待确认。时间由系统提供给模型，确认时仍应核对实际时间和要求。

到时会创建一个新会话执行要求。忙碌时等待名额，不会因为没有空闲名额就直接丢弃任务。同一个预约还没结束时，不会重叠启动；积压的 Cron 触发会合并补跑一次。

预约不等于长期批准写操作。需要写入时仍会停在确认步骤，管理员打开助手后批准；过期则不执行。暂停或删除预约不取消已经开始的任务，应到相应会话停止。

在助手设置中打开「预约通知」后，会通过默认 Bot 发送执行结果或待确认提醒。默认关闭，不会自行向消息渠道发送会话内容。

系统重启后，已经开始却没完成的任务标记为「已中断」，不会自动重放不确定的操作。尚未开始且已到时间的预约会补跑一次。

## 用量和数据

默认每次最多 8 轮、16 次工具调用、32000 Token 预算，单步超时 120 秒。预算包含重复发送的上下文和工具定义，并保守估算，不等同于服务商账单。服务商拒绝请求或超时也可能计费，请以其账单为准。

系统最多保留 100 个会话、每个会话 80 条消息、200 次执行记录、100 条记忆、50 项自定义技能和 20 份反馈草稿；活动中的任务会保留到结束，结果不确定的反馈草稿不自动淘汰。单个会话还有大小限制，过长时移除最早的消息。较长普通工具结果会标明截断；技能分页和待提交反馈保留完整内容，但仍受本次上下文预算限制。SQLite 操作在线程中完成，不需要 Redis、向量数据库或额外常驻模型。

当前实现借鉴工具调用、按需技能、记忆和预约的交互思路，独立实现，未复制其他项目的业务代码。外部 MCP、跨渠道助手和并行子助手尚未接入。
